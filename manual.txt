【9. GitHub認証（CLIなしでpush）】 GitHub CLI (gh) は必須ではない。
HTTPSのgit pushには、通常のGitHubログインパスワードではなく Personal
Access Token (PAT) を使える。

Fine-grained token作成:
https://github.com/settings/personal-access-tokens/new

推奨設定: Resource owner : ShineiFujii Repository access : Only select
repositories Repository : ShineiFujii.github.io Repository permissions →
Contents : Read and write Expiration : 90 daysなど適切な有効期限

PermissionsでAdd permissionsを押し、 検索欄にContentsと入力して選ぶ。
「Repo」で検索するとContentsが出ない場合がある。

トークンは生成時にしか全文表示されない。
パスワードと同様に秘密として扱い、Gitにコミットしない。
紛失時は新規作成を推奨。Regenerateすると旧Tokenは失効する。

macOS Keychainへの保存設定（認証前に実施推奨）: git config –global
credential.helper osxkeychain

push時: git push origin main Username: ShineiFujii Password:
発行したPATを貼り付ける

パスワード入力中は文字が表示されなくても正常。
1台目のMacではPATでpushに成功した。
2台目のMacでも個別のPATを使うと管理しやすい。
Tokenが期限切れなら新しいTokenで再認証する。
古い認証情報がKeychainに残っている場合は、
macOSの「キーチェーンアクセス」でgithub.comの該当情報を確認。

【10. 2台のMacでの運用】 Mac A: VS Code + Quarto + Git Mac B: Emacs +
Quarto + Git 編集ソフトが異なっても同じ.qmdを編集できる。

ルール: Aで編集→commit/push Bで編集前にpull→編集→commit/push
Aで次回編集前にpull

同じファイルを両方のMacで未同期のまま編集すると Gitの競合（merge
conflict）が起きる可能性がある。 まずgit
statusで未コミット変更がないか確認する。
未コミットの変更があるとpullできない場合があるので、
必要に応じてコミットまたはstashしてから同期する。

【11. 実際に起きた問題と対処】 (1) quarto: command not found
Quartoはインストール成功でもPATHにない場合があった。 2台目では
/Applications/quarto/bin/quarto が存在。 ~/.zshrc
にPATHを追加しsourceして解決を目指した。

(2) brew install quarto が失敗 formulaではなくcask: brew install –cask
    quarto

(3) code . が使えない open -a “Visual Studio Code” . で開くか、VS
    CodeのShell Command設定を行う。

(4) GitHub PagesのbuildがFailure Actionsのbuildログを確認。
    会話ではJekyllが起動していたため、 docs出力、docs/.nojekyll、Pages
    main/docs を設定。 原因の確定には実際のActionsエラーログが必要。

(5) GitHub認証エラー Password authentication is not supported →
    通常パスワードではなくPATを使う。

(6) GitHub CLIのHomebrewインストール失敗 古いIntel macOS環境でCommand
    Line Toolsが非対応と表示。 ghは必須ではないため、PAT方式で解決した。
    CLTを削除・再インストールする前に必要性を確認する。

(7) git commit時のユーザー名・メール警告
    GitがMacのホスト名から自動設定したことがあった。 明示設定するなら:
    git config –global user.name “Shin-ei Fujii” git config –global
    user.email “GitHubに登録したメールまたはnoreplyアドレス”
    公開コミットに個人メールを載せたくない場合は、
    GitHubのnoreplyアドレスを使用する。
    既存コミットの著者情報はこの設定だけでは変わらない。

(8) pushしたのにページが変わらない quarto
    renderの実行、docs/のコミット、 Pages
    main/docs設定、Actionsの結果、ブラウザキャッシュを確認。
